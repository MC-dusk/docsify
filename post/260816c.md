# Windows 文件关联机制深度解析 —— 以 mpv 播放器为例

> 本文基于实际折腾 mpv 播放器的文件关联配置经验，梳理 Windows 文件关联的注册表体系、命令解析机制，以及常见踩坑与解决方案。

## 一、问题背景

在 Windows 上为 mpv 配置视频文件关联时，遇到了几个典型问题：

- 使用 mpv 的 `.reg` 注册应用后，所有视频文件类型统一变成了 `mpv Media File`，导致资源管理器中**按类型排序失效**。
- 使用 Default Programs Editor 清除文件类型后，**MediaInfo 右键菜单消失**、**文件预览缩略图丢失**。
- 注册表 `command` 中写的是相对路径（如 `mpv.exe -- "%L"`），程序也不在 PATH 中，为什么还能正常打开？

这些问题促使我深入研究了 Windows 文件关联的底层机制。

## 二、文件关联的注册表路径体系

Windows 文件关联（File Association）的路径分布在多个注册表位置，系统按特定优先级顺序读取：

### 2.1 核心关联路径（按优先级排序）

| 优先级   | 注册表路径                                                   | 说明                                                         |
| -------- | ------------------------------------------------------------ | ------------------------------------------------------------ |
| **最高** | `HKCU\Software\Microsoft\Windows\CurrentVersion\Explorer\FileExts\.扩展名` | 当前用户的文件扩展名关联，包含 `OpenWithList`、`OpenWithProgids` 和 `UserChoice` 子键。其中 `UserChoice` 是用户在"设置"中手动选择的默认程序，具有最高优先级 |
| 次高     | `HKCU\Software\Classes\.扩展名`                              | 当前用户级别的扩展名到 ProgID 的映射                         |
| 中等     | `HKLM\SOFTWARE\Classes\.扩展名`                              | 系统全局的扩展名到 ProgID 的映射                             |
| 基础     | `HKEY_CLASSES_ROOT\.扩展名`                                  | 虚拟合并视图，由 `HKCU\Software\Classes` 和 `HKLM\SOFTWARE\Classes` 合并而成 |

### 2.2 ProgID 对应的命令路径

当扩展名映射到一个 ProgID（如 `txtfile`、`Word.Document.12`）后，实际的执行命令存储在：

```
HKEY_CLASSES_ROOT\<ProgID>\shell\open\command
```

例如：

```
HKEY_CLASSES_ROOT\txtfile\shell\open\command
→ (默认) = "C:\Windows\notepad.exe" "%1"
```

### 2.3 其他相关路径

| 路径                                                         | 用途                               |
| ------------------------------------------------------------ | ---------------------------------- |
| `HKLM\SOFTWARE\RegisteredApplications`                       | 已注册的应用程序                   |
| `HKCU\Software\RegisteredApplications`                       | 当前用户已注册的应用程序           |
| `HKLM\SOFTWARE\Clients\<类别>\<应用名>\Capabilities\FileAssociations` | 应用程序能力声明（Windows Vista+） |
| `HKEY_CLASSES_ROOT\Applications\<可执行文件名>\shell\open\command` | 旧版兼容（已弃用但仍可能被读取）   |

### 2.4 以 `.mkv` 为例的完整路径图

```
HKEY_CLASSES_ROOT\.mkv                          ← 虚拟合并视图
├── (默认) = "mpvnet.mkv"                       ← 映射到 ProgID
│
HKEY_CLASSES_ROOT\io.mpv.file                   ← ProgID 定义
├── (默认) = "mpv Media File"                   ← 文件类型友好名称
├── FriendlyTypeName                            ← 本地化类型名
├── DefaultIcon                                 ← 缩略图/图标
├── shell\open\command                          ← 打开命令
│
HKEY_CURRENT_USER\...\FileExts\.mkv             ← 用户选择
├── OpenWithList                                ← 打开方式列表
├── OpenWithProgids                             ← 关联的 ProgID 列表
├── UserChoice                                  ← 用户最终选择
│
HKEY_CLASSES_ROOT\Applications\mpv.exe          ← 应用程序回退定义
├── SupportedTypes                              ← 支持的文件类型
├── shell\open\command                          ← 打开命令
│
HKEY_CLASSES_ROOT\SystemFileAssociations\.mkv   ← 系统级文件关联
├── Shell\MediaInfo                             ← 右键菜单扩展（如 MediaInfo）
```

## 三、文件关联命令的解析机制

### 3.1 核心问题：相对路径如何被找到？

当 `shell\open\command` 中写的是非绝对路径（如 `mpv.exe -- "%L"`），且该程序不在系统 PATH 中时，Windows Shell **并不会**像命令行那样遍历 PATH 查找。

### 3.2 核心机制：App Paths

Windows Shell 在解析文件关联命令时，会优先查询 **App Paths** 注册表键：

```
HKEY_LOCAL_MACHINE\SOFTWARE\Microsoft\Windows\CurrentVersion\App Paths\mpv.exe
HKEY_CURRENT_USER\Software\Microsoft\Windows\CurrentVersion\App Paths\mpv.exe
```

该键的结构：

| 值名称   | 类型   | 数据示例                       | 说明                           |
| -------- | ------ | ------------------------------ | ------------------------------ |
| `(默认)` | REG_SZ | `C:\Program Files\mpv\mpv.exe` | 完整绝对路径，真正被执行的程序 |
| `Path`   | REG_SZ | `C:\Program Files\mpv`         | 可选，作为该进程的额外搜索路径 |

> **关键点**：`shell\open\command` 中的 `mpv.exe` 在这里仅充当**逻辑标识符/别名**，Shell 拿到文件名后先去 App Paths 查有没有对应的完整路径映射，找到了就用绝对路径启动。

### 3.3 完整解析优先级

当 Shell 遇到 `mpv.exe -- "%L"` 这样的命令时，解析顺序为：

```
1. App Paths 查找
   → 查询 HKLM 和 HKCU 下的 App Paths\mpv.exe
   → 找到 (默认) 值则直接使用绝对路径 ✅

2. 已知应用程序缓存
   → Shell 内部维护的已解析路径缓存

3. 标准 CreateProcess 搜索序列
   → 调用进程所在目录
   → 系统目录 (System32)
   → Windows 目录
   → 当前工作目录
   → PATH 环境变量中的目录

4. 全部失败
   → 弹出"选择打开方式"对话框或报错
```

### 3.4 验证方法

在 PowerShell 中检查 mpv 是否注册了 App Paths：

```powershell
# 检查 HKLM
Get-ItemProperty "HKLM:\SOFTWARE\Microsoft\Windows\CurrentVersion\App Paths\mpv.exe" -ErrorAction SilentlyContinue

# 检查 HKCU
Get-ItemProperty "HKCU:\Software\Microsoft\Windows\CurrentVersion\App Paths\mpv.exe" -ErrorAction SilentlyContinue
```

### 3.5 与命令行的区别

| 场景                          | 是否查询 App Paths | 搜索方式                              |
| ----------------------------- | ------------------ | ------------------------------------- |
| 资源管理器双击文件            | ✅ 是               | App Paths → 缓存 → CreateProcess 序列 |
| CMD / PowerShell 直接输入命令 | ❌ 否               | 仅走 PATH 搜索                        |

这就是为什么在 CMD 中输入 `mpv` 提示找不到，但双击视频文件却能正常用 mpv 打开的原因。

## 四、实战踩坑与解决方案

### 4.1 坑一：文件类型统一变成 "mpv Media File"

**现象**：使用 mpv 的 `.reg` 注册后，所有视频文件（mkv、mp4、avi...）在资源管理器中显示为同一类型 `mpv Media File`，按类型排序失效。

**原因**：所有扩展名都映射到了同一个 ProgID（如 `io.mpv.file`），该 ProgID 的友好名称统一为 `mpv Media File`。

**解决方案**：不使用自定义 ProgID，改用 `Applications\mpv.exe` 路径，让文件类型回退为默认的"后缀+文件"格式（如"MKV 文件"）：

```reg
Windows Registry Editor Version 5.00

; 使用 Applications 路径而非自定义 ProgID
[HKEY_CLASSES_ROOT\Applications\mpv.exe\shell\open\command]
@="\"C:\\Program Files\\mpv\\mpv.exe\" -- \"%L\""

; 声明支持的文件类型
[HKEY_CLASSES_ROOT\Applications\mpv.exe\SupportedTypes]
".mkv"=""
".mp4"=""
".avi"=""
```

### 4.2 坑二：清除文件类型导致右键菜单和缩略图丢失

**现象**：使用 Default Programs Editor 清除文件类型后：
- MediaInfo 右键菜单消失
- 文件预览缩略图丢失

**原因**：清除操作删除了 `HKEY_CLASSES_ROOT\.mkv` 等扩展名键，导致依赖这些键的 Shell 扩展（如 `SystemFileAssociations\.mkv\Shell\MediaInfo`）和缩略图处理程序（ShellEx）失去关联。

**教训**：修改文件关联时，不要暴力删除扩展名键，应仅修改 `UserChoice` 或 `command` 值。

### 4.3 坑三：UserChoice 受哈希保护

从 Windows 8 开始，`FileExts\.扩展名\UserChoice` 键值带有**哈希校验**，不能直接通过注册表编辑器或脚本修改，否则会被系统忽略或重置。

**正确做法**：
- 使用 `IApplicationAssociationRegistration` COM 接口
- 或通过系统"设置 → 默认应用"界面更改

## 五、实用注册表脚本

### 5.1 为 mpv 注册 MKV 文件关联

```reg
Windows Registry Editor Version 5.00

[HKEY_CURRENT_USER\Software\Classes\io.mpv.mkv]
"FriendlyTypeName"="mpv mkv file"
@="mpv"

[HKEY_CURRENT_USER\Software\Classes\io.mpv.mkv\shell]
@="open"

[HKEY_CURRENT_USER\Software\Classes\io.mpv.mkv\shell\open\command]
@="mpv.exe -- \"%L\""
```

> ⚠️ 此方式会导致文件类型显示为自定义名称。如需保留原始类型名，建议使用 `Applications\mpv.exe` 方案。

### 5.2 删除 MP3 文件扩展名关联

```reg
Windows Registry Editor Version 5.00

[-HKEY_LOCAL_MACHINE\Software\Classes\.mp3]
[-HKEY_CURRENT_USER\Software\Classes\.mp3]
[-HKEY_CURRENT_USER\Software\Microsoft\Windows\CurrentVersion\Explorer\FileExts\.mp3]
```

> ⚠️ 暴力删除扩展名键可能导致关联的右键菜单和缩略图丢失，请谨慎操作。

### 5.3 排查 .py 文件打开方式

Python 文件的打开方式涉及以下路径：

```
HKEY_CLASSES_ROOT\.py
HKEY_CLASSES_ROOT\py_auto_file\shell\open\command
HKEY_CURRENT_USER\Software\Classes\py_auto_file\shell\open\command
HKEY_CURRENT_USER\Software\Microsoft\Windows\CurrentVersion\Explorer\FileExts\.py
```

## 六、最佳实践总结

| 建议                     | 说明                             |
| ------------------------ | -------------------------------- |
| `command` 中使用绝对路径 | 避免依赖隐式解析带来的不确定性   |
| 同时注册 App Paths       | 确保 Shell 能正确定位可执行文件  |
| 避免使用统一 ProgID      | 防止所有文件类型显示为同一名称   |
| 不要暴力删除扩展名键     | 可能破坏 Shell 扩展和缩略图      |
| 修改前备份注册表         | 错误操作可能导致系统不稳定       |
| UserChoice 走系统设置    | 不要尝试直接修改带哈希保护的键值 |

## 七、排查思路速查

当文件关联异常时，按以下顺序排查：

```
1. HKCU\...\FileExts\.ext\UserChoice    ← 用户最终选择
2. HKCU\Software\Classes\.ext           ← 用户级映射
3. HKLM\SOFTWARE\Classes\.ext           ← 系统级映射
4. App Paths\<程序名>                    ← 程序路径解析
5. SystemFileAssociations\.ext          ← Shell 扩展（右键菜单等）
```
